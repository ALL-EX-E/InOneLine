InOneLine — автоматический проверочный комплект v1.6 (DonationAlerts: синхронизация интерфейса)
Работает на Windows 11. Python устанавливать не требуется.

ПОРЯДОК ЗАПУСКА
1. Установите приложенный InOneLine_Setup_1.0.8.exe. Перед установкой сохраните резервную копию данных.
2. Скопируйте два файла Start_InOneLine_AutoTest.cmd и InOneLine_AutoTest.ps1 в папку, где находится InOneLine.exe (например, C:\InOneLine).
3. Закройте программу InOneLine, если она запущена.
4. Дважды щёлкните Start_InOneLine_AutoTest.cmd.
5. Скрипт проведёт изолированные проверки, запустит InOneLine и проверит локальный API и адреса OBS-виджетов.
6. В появившемся окне (Y/N) можно согласиться отправить одно сообщение Twitch. Если не хотите проверять реальный Twitch — введите N. Сценарий с проверкой чата НЕ отправляет сообщение самостоятельно, это делает только пользователь.
7. После Twitch появится отдельный НЕОБЯЗАТЕЛЬНЫЙ тест DonationAlerts. Если согласитесь, скрипт покажет уникальное имя тестовой записи. В кабинете DonationAlerts самостоятельно нажмите «Добавить сообщение» (БЕЗ реального платежа) и введите это имя. Время измеряется от нажатия Enter до появления записи в локальном API; оно ВКЛЮЧАЕТ время действий пользователя. Затем проверьте, появилась ли запись во вкладке «Публичный список» БЕЗ F5. Ответьте Y/N/? — это подтвердит или опровергнет автоматическое обновление UI. Можно выбрать N и пропустить.\n8. Когда скрипт попросит, закройте основное окно InOneLine обычным крестиком и нажмите Enter в окне скрипта.
9. Отправьте файл InOneLine_AutoTest_YYYYMMDD_HHMMSS.zip, созданный на рабочем столе, для разбора результатов.

ВАЖНО
— Донаты RUB/EUR эмулируются в отдельной временной SQLite-базе. Они не поступают на настоящий счёт DonationAlerts и не изменяют рабочий аукцион.
— Проверки настоящих наград Twitch отмечаются SKIP: они пока недоступны на вашем канале.
— Проверка настоящего ОПЛАЧЕННОГО доната остаётся SKIP. Отдельное «Добавить сообщение» в DonationAlerts — это НЕОПЛАЧИВАЕМОЕ тестовое событие, а не проверка денежных переводов.\n— Необязательное добавление тестового сообщения МОЖЕТ СОЗДАТЬ одну обычную запись в настоящем списке InOneLine. Перед запуском сделайте резервную копию. Программа и скрипт сами не удаляют рабочие данные. Если не хотите такого изменения — выберите N.\n— Сценарий не входит в тестовое финансирование и не обращается к API DonationAlerts от вашего имени. Проверяется только результат чтения локального API и ручное подтверждение интерфейса.
— Скрипт проверяет доступность HTTP API и адресов OBS, но не оценивает визуальную правильность анимаций.
— Скрипт не включает в отчёт базу данных, пароли, токены и текст сообщений чата.
— Если запустить проверку при открытой InOneLine, она сообщит об ошибке и не будет управлять существующей копией.
— Если API занят другим приложением или Windows запрещает получать порт по PID, будет честная ошибка, а не ложное подтверждение.
— При штатном закрытии долгая запись резервной копии может задержать исчезновение процесса.

ПОКРЫТИЕ ВЕРСИИ V1.6
1. Отдельная тестовая база: сценарии DonationAlerts, защита от дублей и некорректных входных данных.
1А. Вкладка «Список» в изолированной базе: добавление и редактирование через настоящую форму с проверкой сохранения; поиск/выделение; архивирование и восстановление; защита от одинаковых названий.
1Б. Импорт CSV через настоящую кнопку: объединение записей и баллы 0; проверка резервной копии; атомарный отказ при ошибке; старый формат Название|Баллы. Все файлы создаются исключительно в новой временной папке.
1В. Совместная XLSX-таблица во временной среде: создание, подключение, изменение, синхронизация, отключение без удаления файла и повторное подключение. Ни Google Drive Desktop, ни реальный XLSX пользователя не открываются.
1Г. Удаление одной записи и очистка всего списка в отдельной временной SQLite: реальное подтверждение/отмена, настоящий backup в отдельном процессе, сохранность остальных записей и закрытой истории аукциона. Эти действия никогда не выполняются над рабочим списком пользователя.
1Д. Публичный список в отдельной базе: поиск и выделение, три одноразовых экспорта CSV/JSON/XLSX, создание одностороннего XLSX-зеркала, обновление и восстановление файла, отключение и повторное подключение без импорта чужих правок.
1Е. DonationAlerts UI: новое синтетическое событие поступает из фонового Python-потока и без F5 обновляет публичный список, основную таблицу и журнал. ID не начисляется повторно.\n2. Отдельное окно Qt: обход всех девяти основных вкладок.
3. Установленное приложение: запуск, HTTP API и пути OBS, обычное завершение процесса.
4. Необязательная интерактивная отправка сообщения Twitch.\n5. Необязательное добавление сообщения из реального кабинета DonationAlerts без оплаты; поиск по уникальному тестовому названию через локальный HTTP и ручная проверка обновления Public без F5.

Это ограниченная версия тестировщика. Проверка всех отдельных кнопок и анимаций требует отдельной дальнейшей реализации.
