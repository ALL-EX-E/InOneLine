# Сверка публичных возможностей перед 1.0.11

Дата: 12.11.2026. Публичная база: тег `v1.0.10`, коммит `5a70f926c6d2ee3eb5f2aa447c48e5cbfc05e3ff`. Проверенная принятая реализация: `0049b2bda23f60fb8f1f3a20f0f57476e9ec041b`; последующие изменения main до подготовки выпуска — документация. Между базой и принятой реализацией шесть продуктовых/maintenance PR: №423–428. Исторический ручной PASS этих пакетов и независимые Windows-проверки записаны в PROJECT_STATE; новый установщик 1.0.11 требует отдельной приёмки.

## Цель и границы

Привести описание GitHub к реализованным функциям и подготовить следующий выпуск. Сохранить принятую логику, схему 21, данные и отложенную очередь. Допустимые изменения исполняемого кода — только APP_VERSION; номера установщика и ожидаемая версия QA обновляются согласованно. Ни одна новая функция дорожной карты не реализуется.

## План и проверка

1. Зафиксировать паузу разработки и завершение первого прохода очереди в рабочем документе и его точной Drive-копии.
2. Обновить README и отдельное полное описание возможностей, устранить смешение импортов/экспортов и невыданные обещания интеграций. Подготовить release notes 1.0.11 и короткий ручной чек-лист.
3. Обновить версию приложения/установщика/ожидания QA. Дополнить существующий Windows workflow упаковкой нового кандидата с исходниками и контрольными суммами.
4. Проверить минимальность diff, wording, автоматическую Windows-регрессию, установку и запуск; скачать точный QA-архив, проверить CRC/SHA-256 и совпадение исходников; выдать его через Drive после обратного скачивания.
5. Получить ручной PASS нового установщика. Затем продвинуть те же байты, дождаться независимой проверки main и опубликовать штатным immutable publication request. Только после подтверждённой публикации переключить публичные ссылки и SHA256SUMS.

Новый номер выбран **1.0.11**: последний опубликованный 1.0.10, после него есть принятые пользовательские функции. Старые релизы и их assets не заменяются. Незавершённые исторические кандидаты автоматически не сливаются.
