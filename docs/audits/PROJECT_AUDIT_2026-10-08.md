## Обнаруженные расхождения и совпадения

- Drive `InOneLine_CURRENT.zip` — исходники 1.0.7, совпадающие с официальным Source 1.0.7 и кандидатом FIX11. Это не актуальный `main`.
- Исходный `main` содержит принятые A4–A9 и P01–P04-C, которых нет в публичном maintenance-релизе 2026-10-01. Их одинаковый APP_VERSION не даёт права подменять архивы.
- P04-D #33 имеет автоматический PASS и остаётся неприёмным кандидатом; этот аудит не закрывает его ручную проверку.
- Найдены 11 групп одинаковых файлов, 15 копий сверх первой. В шести случаях совпадают байты и назначение и нет комментариев: дополнительные экземпляры помещаются в отдельную категорию. Другие совпадения сохраняют самостоятельные роли релиза/отката/кандидата.
- Нативные Google Docs не имеют полностью одинакового извлечённого текста в отдельной группе. Частично совпадающие cumulative-документы сохраняются целиком; новая карта объединяет выводы, не уничтожая уникальные блоки и ссылки на оригиналы.
- Совпадающие manifests ZIP с разной упаковкой учитываются отдельно от побайтовых копий. Имя, дата, comments и роль могут оставаться уникальной информацией даже при равенстве payload.
- Исторические SHA-256 в старых release notes могут отличаться от нынешних GitHub asset digests. Реестр сохраняет обе привязки; равенство или оригинальность не объявляются по одному имени.

Ни один оригинал, коммит, ветка, тег, issue/PR или комментарий не удалён. Перемещения сохраняют Drive ID; журнал содержит исходных/новых родителей и названия для обратного действия.

### Доказательство дефектов

Новые проверки запущены до исправления. GUI-тест завершился на `Hidden invalid interval blocked save: auction_auto_extend_leader_ms invalid`. Проверка CI завершилась на отсутствии guard после `python -m pip install --upgrade pip`. После исправления соответствующие проверки проходят.

GUI покрывает все четыре интервала: неверный текст, нулевое значение и выход за 24 часа при выключенной/включённой причине, сохранение последнего корректного значения, отсутствие частичного сохранения и сохранение допустимого скрытого черновика.

Поведение PowerShell сверено с официальными источниками: [GitHub о shell/exit status](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax), [Microsoft о native-командах](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_error_handling?view=powershell-7.6). GitHub учитывает последний native exit code; ненулевой код по умолчанию не является terminating PowerShell error. Поэтому следующий успешный Python-процесс мог маскировать предыдущий сбой.

## Полный ручной чек-лист данного кандидата

1. На тестовой Windows-установке открыть «Настройки → Аукцион». Для каждой причины и порога включить поле, ввести неверный текст, выключить причину и сохранить. Ожидание: сохранение разрешено, причина выключена, восстанавливается последний корректный интервал.
2. Повторить с `00:00:00.000` и `25:00:00.000`. Ожидание: скрытое неверное поле не блокирует сохранение; допустимое предыдущее значение сохранено.
3. Включить причину и сохранить такое же неверное значение. Ожидание: понятное предупреждение; ни интервал, ни флаг, ни остальные настройки не записываются частично.
4. Ввести допустимые `00:00:12.345`, выключить причину и сохранить. Ожидание: сохраняется именно новый допустимый интервал. После включения и перезапуска он восстанавливается.
5. На тестовых данных выполнить штатную SQLite/полную backup/restore-проверку. Ожидание: предварительная проверка работает, штатное восстановление успешно, отрицательная проверка отката подтверждает достижение внедрённого отказа.
6. Проверить Windows CI этого точного коммита. Ожидание: 13 отрицательных PowerShell-проб и три положительных последовательности прошли, затем постоянные регрессии/сборка/установка прошли; опубликованные релизы остались прежними.

Проверять сценарии с копией данных. Установщик-кандидат не считается принятым релизом.
