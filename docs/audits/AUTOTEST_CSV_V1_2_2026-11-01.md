## Проверенное текущее поведение
- AutoTest v1.1 выполняет 11 изолированных проверок, в том числе 5 сценариев списка (создание, поиск, редактирование, архив, дубликат). Импорт CSV пока не покрыт.
- `GamesTab.import_csv()`: выбирает файл через `QFileDialog.getOpenFileName`; запускает `FunctionWorker` в `QThreadPool`; в worker выполняет **резервную копию до импорта** через `Database.import_csv_with_backup`; по результату обновляет таблицу и показывает QMessageBox. Управление кнопками временно блокируется.
- `Database.import_csv` поддерживает заголовки «НАЗВАНИЕ;БАЛЛЫ;ДАТА» и алиасы, а также старый `Название|Баллы`. Проверяет файл полностью до первой записи, выполняет атомарную транзакцию; пустые ячейки не должны стирать имеющиеся поля, явный ноль баллов должен применяться.
- Полные нативные тесты `tools/gui_regression_smoke.py` покрывают строгий парсер, русские тексты ошибок, пустой/старый CSV и атомарность, но операторский пользовательский ZIP пока не включает самостоятельные случаи импорта.

## AUTO-TEST-002B: минимальный состав
1. **Только в изолированном временном корне** через настоящий путь кнопки «Импорт CSV», файловый диалог программно подменяется одноразовым заранее заданным временным файлом. Настоящий диалог, пользовательский CSV и его Google Drive не открываются.
2. Проверить нормальный CSV: новую запись, обновление существующей, явное значение баллов 0, сохранение ранее заполненного отзыва при пустой ячейке, создание реальной safety-backup, обновление таблицы/сводки и завершение фонового worker.
3. Проверить ошибочный CSV с валидной строкой перед невалидной: ошибка показывается, ни одна из строк не внесена, тестовая база и существующая запись остаются целыми, для этого запуска отдельно создан safety-backup.
4. Проверить совместимость старого формата `Название|Баллы` и результат на таблице/в SQLite.
5. Каждая категория получает отдельный PASS/FAIL с кодом ошибки в отчёте. Ни один synthetic CSV не копируется в отчёт. Временные файлы, backup и БД удаляются после проверки.
6. Сохранить v1.1; проверка source и frozen Windows, нативная GUI/XLSX регрессия, завершение EXE, собранный installer, GitHub Actions artifact и Google Drive. Только после CI — пользовательская установка и повторный ZIP-отчёт. Не заявлять полный охват CSV, XLSX, удалений, OBS-анимаций.

**Критерии безопасности:** никакой загрузки пользовательских реальных данных, не отключать safety-backup и не имитировать его успешное завершение, не пропускать реальные db-операции в тестовой ветке. Никаких изменений runtime CSV-импортера.

Статус: карточка записана до реализации.


## Результат и ручная приёмка

**Реализация AUTO-TEST-002B:** три сценария записаны в `streaming_manager/operator_autotest.py` и вызывают настоящее `GamesTab.import_csv` через кнопку. `QFileDialog` подменяется только в временном Qt sandbox для выдачи synthetic CSV, а `QMessageBox` фиксирует ожидаемый успех/ошибку; остальной путь не подменяется: `FunctionWorker` → `Database.import_csv_with_backup` → отдельный subprocess safety-backup → валидация/атомарная транзакция → `GamesTab` обновление UI. Проверки: merge и явные нулевые баллы без потери предыдущего отзыва; ошибка после валидной строки без частичной записи; legacy `Название|Баллы`. Каждый backup проверяется `PRAGMA integrity_check=ok`; UI/SQLite состояние сверяются. Всего **14** тестов против прежних 11.

**Обнаруженный дефект только тестировщика:** в первом CI три CSV-сценария были PASS, но `TemporaryDirectory` на Windows не мог удалить файл backup (WinError 32). Причина: `with sqlite3.connect(...) as copied` подтверждает транзакцию, но не закрывает файловое соединение; Windows сохранял блокировку. Исправлено явным `contextlib.closing(sqlite3.connect(...))` **только внутри тестировщика**, без изменения импортера/backup в программе. Повторная проверка очистки PASS. Диагностика тестовой среды ограниченно фиксирует `error_type/error_message` только при FAIL, не копируя пользовательскую БД или данные.
