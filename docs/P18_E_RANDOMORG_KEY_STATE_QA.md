# P18-E / UI-084 — состояние сохранённого и временного RANDOM.ORG API-ключа

Дата: 2026-10-18. Основа: вручную принятый P18-D, QA 5/5 PASS; его чистый exact-tree PR #254 и контрольный Windows CI должны быть успешно завершены до ручной P18-E.

## Scope

Существующие `QLineEdit.Password`, `CredentialStore`, `RandomOrgClient.get_usage()`, `Проверить API` (асинхронная проверка и показ оставшихся requests/bits) и `Сохранить ключ` остаются без изменения принципа работы.

- Ввод и проверка ключа не пишут credential в постоянное защищённое хранилище и не влияют на аукцион. Только явное нажатие `Сохранить ключ` вызывает `db.set_random_org_api_key(...)` и существующий `random_org_key_changed()`.
- Временно введённый и проверенный рабочий ключ помечается `API работает. Ключ ещё не сохранён.`; если проверен именно сохранённый ключ — `API работает. Ключ сохранён.` В обоих случаях реальные requests/bits показываются как раньше.
- Ручное изменение поля помечается как `ключ изменён, но ещё не сохранён`, если оно отличается от persisted credential; даже очистка поля сама по себе не удаляет сохранённый ключ.
- На время фонового запроса запоминается только временный локальный snapshot проверяемого ключа; если текст изменили во время ожидания, результат не должен ложно удостоверять новый текст поля. Snapshot очищается после завершения запроса.
- Ошибка внешнего API не сохраняет/не очищает ключ и сообщается как неудачная проверка. Никакие значения ключей не выводятся пользователю в status/dialog/log.
- Очистка поля + `Сохранить ключ` удаляет сохранённые данные, как и до изменений; изменение обоснованно сигнализируется остальным функциям.
- Без новых таблиц и без изменений RandomOrgClient, генерации колеса, протокола Random.org, SQLite-схемы, Twitch/DonationAlerts.

Изменения строго в `streaming_manager/views/settings.py`, изолированный Qt smoke `tools/random_org_key_state_smoke.py`, обязательная Windows CI-regression и этот документ.

## Ручная приёмка (5 отдельных проверок)

1. Ввести временный тестовый/действительный ключ в поле RANDOM.ORG и нажать `Проверить API`: при успешной проверке появляется `Ключ ещё не сохранён`. Никакого сохранения без Save.
2. Нажать `Сохранить ключ`, после этого повторная `Проверить API` должна показывать `Ключ сохранён` и реальные requests/bits; аукцион получает сохранённый ключ.
3. Изменить ранее сохранённый текст на другой; статус `не сохранён`; проверка второго значения не перезаписывает сохранённый без Save. При отсутствии второго действительного ключа этот сценарий проверяется автоматикой, не нужно заведомо расходовать лимит.
4. Очистить поле: статус `не сохранён`, сохранённый credential пока не удалён. `Сохранить ключ` явно очищает credential; UI и доступность соответствуют текущему состоянию.
5. Перезапустить программу и проверить что отображается только реально сохранённое значение, история/колесо/Twitch/DonationAlerts без регрессий.
