# P22-B / UI-080 — шаг 3: вкладка «Проверка результата» только после вращения

**Изолированный QA-кандидат, пока не принят пользователем.** Только ранее утверждённый пункт №3 UI-080 из docs/ACTIVE_REVIEW_LEDGER.md. Этап #2 (фактический путь режима в Истории) принят вручную и переносится в main отдельно.

## Что именно меняется

- В существующей вкладке «История аукционов» секция «Проверка результата» показывается **только когда для выбранной закрытой сессии действительно было вращение колеса**.
- Источники: уже существующая `completed_auction_details` → `mode_evidence` (пакетная выборка из `change_log` action=wheel и неизменяемых `wheel_verification_snapshots`). Ни режим `weighted_wheel`, ни выбранное колесо при ничьей, ни переключённый формат без `wheel`/snapshot не считаются совершённым вращением.
- Для Max Amount без spin вкладку скрыть; для реального колеса (в том числе Max → tie-wheel) показывать. В старом колесе без immutable snapshot, но с сохранённым событием `wheel`, вкладка показывает штатное сообщение об отсутствии проверяемого snapshot — не подделывать историю.
- При смене выбранного закрытого аукциона, очистке, обновлении и F5 вкладка должна немедленно показываться или скрываться по фактам именно новой сессии. Существующие раунды и кнопки проверки результата сохраняются без изменений; положение других вкладок и содержимое «Лоты/События/Общие» не трогать.
- Код использует только `QTabWidget.setTabVisible`, старый механизм `_load_verification_details` вызывается только для реально вращавшихся сессий. Сохранение/архив SQLite, расчёт RNG, snapshots и аудит не изменяются.

## Исключено

- Нет ни новой БД/миграции/таблиц, ни пересоздания snapshot для старых сессий. Никаких изменений в аукционе, правилах, OBS, музыке, конвертации.
- UI-080 #4 (расширение описаний событий истории), UI-081 (оформление общего Журнала), релиз и изменение версии 1.0.8 не входят в этот пакет.

## Автоматические проверки

`python tools/completed_auction_history_verification_visibility_smoke.py` в общем Windows Regression Foundation. Проверяется скрытие у pure Max, выбранного, но не вращавшегося tie-wheel и direct wheel, показ у legacy wheel audit без snapshot с существующим сообщением, у snapshot-only legacy, несколько раундов, переход между выбранными строками и refresh, отсутствие утечки вращения другого аукциона.

Обязателен полный native Windows CI (Qt/Chromium/OBS, frozen app, Inno Setup, silent installed startup) и Publication wording gate.

## Лист ручной Windows проверки

1. Установить exact P22-B UI-080 #3 ZIP поверх принятой 1.0.8; проверить сохранность настроек/истории.
2. Открыть Историю и выбрать чистый завершённый аукцион Максимальная сумма: вкладки «Проверка результата» быть не должно.
3. Открыть завершённый аукцион с реальным вращением: вкладка «Проверка результата» появляется. У прямого колеса и Max → колесо при ничьей поведение одинаковое.
4. Когда колесо только выбирали, но вращения не было, вкладка остаётся скрытой; если таких историй нет, сценарий покрывают автоматические тесты.
5. Если есть старая сессия со spin, но без verification snapshot, вкладка видна с честным сообщением о невозможности точной проверки. В сессии с несколькими раундами доступен выбор сохранённых вращений.
6. Переключать строки с колесом/без, затем F5 и фильтры/поиск. Проверить сортировку, режим и содержимое «Общие/Лоты/События», OBS, Музыка, Журнал; ранее принятое поведение сохраняется.
