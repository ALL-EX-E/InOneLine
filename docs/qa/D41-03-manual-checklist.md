# D41-03 — локальный браузерный мультичат YouTube/Twitch — Windows QA

**Только кандидат. Старые Google OAuth/Data API/list полностью отклонены.** Без подписки, платного сервера, Google Cloud/OAuth ID и внешнего браузера. Единственный браузерный компонент работает локально через Qt WebEngine. Важное юридическое замечание: сайты YouTube и Twitch ограничивают автоматизированный сбор данных; технический QA не означает разрешение платформы.

**Перед началом:** сохранить резервную копию InOneLine, установить D41-03 из прилагаемого архива, Twitch EventSub и его награды до теста оставить без изменений. Длительный 24/7 soak-тест, обрывы соединения и многосуточное восстановление будут проводиться пользователем *после* базовой ручной приёмки, во время использования; о потерянных сообщениях нельзя заявлять, что они восстановлены.

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Запустить Windows-программу и открыть «Мультичат», сверить прежний Twitch EventSub и награды. | Вкладка/виджет OBS работают, награды Twitch сохранены. |
| 2 | Открыть «Настройки → Интеграции». | **Нет** карточки или формы Google OAuth; Twitch/DonationAlerts на месте. |
| 3 | Вставить ссылку `https://www.youtube.com/live_chat?is_popout=1&v=<ID>` от своей трансляции и нажать «Применить». | Ссылка сохраняется, Qt WebEngine загружает этот чат; Google Cloud ID не нужен. |
| 4 | Аналогично проверить ссылку отдельного чата через `https://studio.youtube.com/live_chat?...&v=<ID>`. | Studio URL преобразуется в обычную публичную ссылку того же live chat; вход в Google для чтения публичного чата не нужен. |
| 5 | Вставить `http://...`, чужой домен, обычный `watch?v=`, неверный video ID. | Понятная ошибка, старое подключение не разрушается. |
| 6 | Подключиться посреди действующего эфира с уже имеющейся историей. | Прошлые сообщения не выводятся, только новые после подключения. |
| 7 | Отправить несколько новых сообщений на YouTube. | Появляются в общей вкладке и OBS, без второго чата/задвоений; если нет — сообщить FAIL, привести скриншот без секретов. |
| 8 | Отправить одновременно сообщения на Twitch EventSub и YouTube. | Один хронологический общий поток; разные значки/графика — будущие D41 этапы. |
| 9 | Выключить YouTube в OBS и отправить сообщения, затем включить. | Во вкладке новые видны, в OBS отключённые не появляются задним числом. |
| 10 | Заменить ссылку YouTube на другой достоверный эфир. | Очистится только старая YouTube-лента; Twitch и его разрешения не затрагиваются. |
| 11 | Оставить YouTube-чат без сообщений некоторое время. | Нет ложного статуса ошибки просто из-за тишины; показанные сообщения не удаляются. |
| 12 | Выбрать «Браузерный чат» в способах Twitch. | Появляется подтверждение о возможных дублях и прекращении чтения EventSub; награды продолжают работать. |
| 13 | Отменить подтверждение. | Остался исходный EventSub-режим и прежний поток. |
| 14 | Подтвердить браузерный Twitch, вставить popup URL (`dashboard.twitch.tv/popout/u/<канал>/stream-manager/chat` или `www.twitch.tv/popout/<канал>/chat`). | Ссылка Twitch Dashboard нормализуется к публичному popout соответствующего канала без необходимости входа в отдельный Chromium; новые Twitch-сообщения приходят только через браузер, EventSub для наград сохранён. |
| 15 | Переключить Twitch обратно на EventSub с подтверждением. | Чтение Twitch через браузер прекращено; при действующих правах снова работает официальный EventSub; награды не затронуты. |
| 16 | Проверить пустой чат и содержимое с HTML-символами, изменения размеров окна 520×360 и 2560×1440, перезапустить программу. | Нет исполнения HTML как кода, нет наложений интерфейса, настройки ссылок и способа Twitch сохранены, история RAM после перезапуска пуста, OBS-виджет не перестал работать. |

| 17 | На YouTube отправить сообщение, убедиться, что оно пришло в InOneLine и OBS, затем удалить его в YouTube-чате. | При распознаваемом браузером признаке удаления исходное сообщение исчезает из обеих лент и буфера; другие сообщения не меняются. |
| 18 | Переключить Twitch на браузерный режим, отправить и затем удалить своё сообщение в Twitch; повторить удаление через модерацию, если доступно. | При полученном признаке модерации соответствующее сообщение автоматически исчезает из вкладки InOneLine и OBS. Сам текст заглушки удаления не появляется новым сообщением. |
| 19 | После появления нескольких сообщений дождаться обычной прокрутки и удаления старых HTML-строк браузером; проверить сообщения другой платформы. | Обычная виртуализация/прокрутка HTML не принимается за удаление; чужие сообщения остаются. |

**FIX D41-03 / обнаружено на ручном QA 25.10.2026:** отсутствие реакции на удалённые сообщения в браузерных YouTube и Twitch. Для этого кандидата предыдущие 16 проверок сохраняются; пункты 17–19 добавлены как адресная проверка исправления. Реальная DOM-разметка сайтов изменчива. Если площадка полностью убирает строку без наблюдаемого однозначного сигнала удаления и соответствующего ID, удалять сообщение наугад нельзя — отметить «НЕ ПРОВЕРЕНО» или FAIL с безопасными диагностическими данными, не считать это гарантированным PASS. Ни OAuth, ни API-поллинг не вводить.

| 20 | Подключить YouTube, затем в браузерном режиме Twitch. Отправить на обе платформы по два НОВЫХ сообщения после подключения обеих. | Оба чата продолжают принимать одновременно; ранее подключённая платформа не останавливается. Сообщения приходят в общую вкладку и OBS независимо. |
| 21 | Не закрывая программу, повторно применить тот же YouTube URL; затем заменить YouTube URL на другой действующий эфир. Отправить новые сообщения на Twitch и в новый эфир YouTube. | Смена действительно другого эфира очищает только старые YouTube-сообщения, новый YouTube работает, Twitch не прерывается. Повтор того же URL не создаёт дубли. |
| 22 | При одновременном подключении заменить Twitch URL на другой действующий канал; проверить новые сообщения на YouTube и Twitch. | Оба источника продолжают работу; только Twitch меняет канал, YouTube остаётся подключённым. |
| 23 | В новом FIX повторить удаление собственных сообщений на YouTube и Twitch с открытым видимым чатом, а также удалить одно сообщение другого автора через модерацию, если доступно. | Удаление полученного сообщения отражается в обеих лентах, не затрагивает соседние сообщения и не порождает текстовые дубли. Если не исчезло, это FAIL с указанием платформы, режима и скриншотом без секретов. |

**D41-03 FIX2 — ручной FAIL 25.10.2026:** пользователь подтвердил, что FIX1 не удаляет сообщения, что второй браузерный источник останавливает первый, а изменение ссылки не восстанавливает чтение. Предыдущие одиночные PASS не засчитывать за 20–23. Сначала проверить реальную доставку сообщений на ОБЕИХ платформах после подключения каждой, затем смену ссылок и удаления. Проверка по одному изолированному чату недостаточна.

**Отчёт:** PASS / FAIL / НЕ ПРОВЕРЕНО по каждому из 23 пунктов. Скриншоты и логи без приватных cookie/токенов. Не считать первый CI доказательством работы на реальных YouTube/Twitch DOM. Любой подтверждённый FAIL — FIX того же PR №376 с повторной Windows QA. До отдельного «Принимаю» не сливать в main, не публиковать релиз, не начинать следующий пакет. Длительная проверка в эксплуатации может повторно открыть пакет при найденных сбоях.
