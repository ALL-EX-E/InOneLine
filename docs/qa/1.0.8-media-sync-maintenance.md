# InOneLine 1.0.8 — A4 Managed Media Sync Maintenance

Status: **MERGED / MANUALLY ACCEPTED**

Date: **2026-10-02**

## Scope

Maintenance scope A4 from the 2026-10-01 codebase audit.

Goal: preserve the existing managed-media API and D26 behavior while removing the per-file SQLite reopen/rescan pattern in `sync_managed_media_category()`.

Before A4, syncing 20 managed music files caused 22 SQLite connections. The accepted implementation performs one directory scan and one SQLite connection/transaction per category sync regardless of library size.

No APP_VERSION, schema, migration-count or normal release-cadence change.

## Accepted behavior

- one SQLite connection/transaction per managed-media category sync;
- one initial managed-row query and one managed-name index;
- insert only missing managed rows;
- remove stale managed rows only for D26 `music` / `soundtrack`;
- preserve existing IDs and `original_name`;
- preserve external media rows;
- preserve established non-D26 missing-file recovery behavior;
- repeated sync remains idempotent;
- unsupported files remain ignored.
