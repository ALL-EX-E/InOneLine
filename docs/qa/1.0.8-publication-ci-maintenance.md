## Accepted design

A7 introduces one future accepted-release publisher:

- `.github/workflows/publish-accepted-release.yml`
- `tools/release_publication.py`
- `tools/publication_ci_smoke.py`
- `docs/RELEASE_PUBLICATION.md`

Normal publication is driven by a newly added immutable request under:

`.github/release/requests/*.json`

Each request records:
- exact accepted Actions artifact ID;
- exact accepted target commit;
- release tag/title;
- Git-tracked release-notes path;
- accepted artifact paths;
- final public asset names;
- exact SHA-256 for each asset.

Publisher safety rules:
- normal main-push publication accepts only a newly added request;
- request modifications are rejected;
- existing GitHub Release or tag is refused before publication;
- target commit must exist and be an ancestor of current main;
- release notes must be Git-tracked;
- exact accepted artifact is downloaded by numeric ID;
- every asset SHA-256 is checked before publication staging;
- files are copied/renamed without rebuilding;
- release is created at the exact accepted target commit;
- published assets are downloaded again and exact names/SHA-256 are re-verified;
- available GitHub asset digests and release metadata are checked.

`workflow_dispatch` remains available only for retrying an existing immutable request after a pre-publication infrastructure failure. It does not weaken existing-tag/release overwrite guards.
