# InOneLine — ручная проверка PR №417: единая совместная область в основном OBS

**Цель:** проверить не перенос отдельных анимаций, а **переиспользование уже принятой совместной области** `IOLListComposition` на месте списка внутри **главного OBS-источника** `/overlay`. Внешняя общая область неподвижна; позиция списка, веб-камеры, инфоблока остаётся прежней. Другие OBS URLs не должны измениться.

## Подготовка

- Установить QA-версию поверх установленной InOneLine (не выпуск/release). Настройки и БД сохранять; при необходимости сначала сделать резервную копию.
- Открыть главный OBS Browser Source `/overlay` с заданным размером холста **2560×1440**. Не подменять его отдельным `/combined-overlay` в OBS: проверяется именно встроенный блок.
- В программе включить объединение Twitch-чата со списком, выбрать **«Разделение области»**; для чата **«Показывать постоянно»**. Для списка использовать сохранение каждого следующего режима кнопкой **«Сохранить»**.
- Установить время анимации списка **2,00 с**. Для режима команды установить время показа **5 с**; оно начинается только после полного завершения выезда.

## Проверка A — сохранение настроек

1. Список **«Показывать постоянно»**, чат **«Показывать постоянно»**: области устойчиво делят контейнер **50/50**, список сверху, чат снизу; никаких повторных анимаций при повторном «Сохранить».
2. Переключить список на **«Не показывать»**, нажать «Сохранить»: список плавно уходит **вверх 2 с** без изменения собственной прозрачности, чат разворачивается снизу до 100%; общий внешний контейнер остаётся на месте. Чат не пропадает и не обновляется заново.
3. Вернуть **«Показывать постоянно»**: список возвращается за **2 с** с использованием принятой анимации, чат возвращается к нижней половине, без рывков и сброса сообщений. Повторное сохранение не запускает анимации.

## Проверка B — команда Twitch, каждый из четырёх направлений

4. Выбрать режим списка **«Выезд»**, команду Twitch, при необходимости настроить длительность 2 с и время показа 5 с. Включить **«Показывать постоянно»** для чата; сам чат может быть пустым или содержать тестовое сообщение.
5. Проверить направления по очереди: **слева, справа, сверху, снизу**. Каждый раз сохранённая Twitch-команда приводит к плавному выезду списка **поверх чата** на собственную верхнюю область, после чего появляется устойчивое разделение **50/50**. Чат не должен сжиматься преждевременно или терять сообщения. Направление «снизу» начинается от границы **собственной верхней половины**, не снизу всего контейнера.
6. После завершения 2-секундного въезда список находится полностью в своей области **5 с**. Затем уходит за **2 с** точно в обратном направлении. Чат вновь занимает доступную высоту; за время анимации нет изменения opacity содержимого списка, мигания iframe и перемещения внешней области.
7. Отдельно проверить, что **камера**, **инфоблок**, **рамка**, **фон оверлея**, **расположение колонки** не изменились и не получают анимацию списка.

## Проверка C — отсутствие нежелательных изменений

8. Открыть отдельные источники `/list-overlay` и `/combined-overlay`, убедиться, что ранее принятые анимации работают **точно так же**, как до интеграции. Отдельный `/multichat-overlay` остаётся независимым.
9. Проверить прежние режимы **«Замещение области»** и **«Скрывать, когда пуст»** — они не должны получить новых движений без отдельного согласования.

**Отчёт:** если все пункты пройдены, сообщить «Всё работает. Принимаю PR №417». Если нет — указать номер проверки, направление и текущее/ожидаемое поведение (по возможности видео). **Никакого merge в main до ручного PASS**.
