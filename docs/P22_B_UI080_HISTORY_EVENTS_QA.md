# UI-080 — шаг №4: понятные события в «Истории аукционов»

Статус: самостоятельный QA-кандидат после принятого пользователем шага №3. До отдельной ручной приёмки не переносить этот кандидат в основную ветку.

## Границы реализации

- **Только представление уже сохранённых событий**, не изменение аукционной логики и не создание нового audit backend. Старые записи `change_log` и их `before_json/after_json` неизменны.
- Читаемые русские события: post-00:00 добавление/уменьшение баллов с фактическим delta и итогом; создание и подтверждённое объединение лотов; переименование временного лота с прежним/новым именем и сохранёнными баллами; исключение постоянного лота без удаления игры/баллов; удаление временного; создание/присоединение целевого лота из ожидающего поступления; пересчёт статуса лидера/ничьей после ручных корректировок и ожидающих поступлений; стоп/повтор **анимации** колеса без приписывания нового RNG; реальный раунд колеса; итог выбывания и сохранённые временные лоты при отмене.
- Небольшое исправление чтения существующего `change_log` для события `post_expiry_title_lot`: его исторический источник `source_auction_id`, а не `auction_id`; теперь такое событие отображается **только у правильной исходной сессии**. Записи других сессий не смешиваются.
- Оставлены прежние русские события начала, паузы, продолжения, изменения таймера, ставок, завершения, ничьей, допвремени, колеса, победителя, отмены. Неизвестные будущие action сохраняют технический fallback вместо потери события.

## Что НЕ входит

- Нельзя придумывать отсутствовавшие исторические `Изменить лот` / абсолютный total / merge / freeze / auto-survivor / UI-065 stop/finalize / UI-067 повторные циклы: пока событие не пишется в текущий `change_log`, его нельзя честно показать. Для действий, чьи фактические payload уже доступны, описание привязано к ним.
- Не добавляем storage/migration/schema, не создаём отдельный журнал, не пересчитываем wheel RNG и позиции ФИНИШ, не трогаем начисления, бизнес-операции и интеграции, UI-081 «Журнал», OBS, музыку, официальную версию 1.0.8.
- Поле `СТАРТ` истории и отсутствие неподтверждённого immutable `ФИНИШ` сохраняются.

## Автоматические проверки

`tools/completed_auction_history_events_smoke.py`: исходные/новые события, delta+итог, переименование, объединение, постоянный лот и баллы, привязка исходного source_auction_id и защита от чужой сессии, выбывание и stop/replay, русские статусы после 00:00, сохранение прежних action и fallback. Запускается на native Windows Regression Foundation вместе с GUI/OBS/Chromium, сборкой и запуском Inno Setup; Publication wording обязателен.

## Ручная Windows проверка

1. Установить только проверенную сборку UI-080 №4 поверх 1.0.8. Список/настройки/история сохраняются.
2. В Истории выбрать аукцион с действиями после 00:00: в «События» названия русские, добавление/уменьшение баллов показывают реальные дельту и итог. Если таких сессий нет, тест покрыт автоматикой.
3. При наличии переименованного/объединённого/исключённого лота видны названия, сохранённые баллы и результат; без неоснованного восстановления старой истории.
4. Проверить при наличии старого аукциона с ожидающим поступлением: целевой лот относится именно к исходной сессии. Проверка источника автоматизирована, создавать новые события специально не требуется.
5. В аукционах с колесом проверить русские действия вращения, архивации, подтверждения и stop/replay. Прежние события паузы, допвремени и отмены остаются читаемыми.
6. Проверить F5, поиск, периоды, сортировку, вкладки «Общие/Лоты/Проверка результата», минимальное окно, OBS и музыку. Данные ставок/игр/результатов не изменились.

После пользовательского PASS продвигать ровно проверенные исходные Git blobs в `main` с новой Windows и postmerge проверкой. Следующая независимая дорожная карта — UI-081.
