# P19-E / UI-085 — явное «Не применять» для ожидающего события

Текущий изолированный пункт #6 из ACTIVE_REVIEW_LEDGER после принятого пользователем P19-D. Версия 1.0.8. **DRAFT — не принят, не сливать в main и не публиковать.**

## Реализация

- В «Настройки → Конвертация → Ожидают применения» добавлена соседняя с «Применить» кнопка **«Не применять»**. Она активна также для неизвестного курса и нулевого предварительного расчёта. Кнопка «Применить» остаётся под действующими ограничениями.
- Перед действием обязательный диалог с игрой, источником, ID события, исходной суммой и ясным предупреждением о необратимости. Нажатие «Нет» или закрытие окна ничего не меняет.
- Явное подтверждение переводит \`pending_conversions.status\` в уже поддерживаемый схемой финальный статус \`cancelled\`, а \`external_events.processing_status\` — тоже в \`cancelled\`; \`external_events.processed_at\` устанавливается в UTC. Всё выполняется **в одной SQLite-транзакции**; ошибка откатывает оба статуса и журнал.
- Исходный \`external_events.payload_json\`, обе исходные строки, \`change_log\` и идентичность \`source + external_event_id\` сохраняются. Новый журнал \`integration_event / reject_pending\` хранит previous/final statuses, pending ID, source, external event ID, тип, исходные game/auction/lot/amount/unit и причину \`operator_no_apply\`. Повторная доставка провайдера отвечает \`duplicate=True\` и **не создаёт начисление**.
- Никаких новых \`games\`, \`contributions\`, изменений game/auction points, таймера/колеса/победителя, провайдерской авторизации, DB schema или UI сохранения курсов. \`set_conversion_rates_atomic\` учитывает только активные статусы — отклонённое событие не возвращается в очередь при смене курса.
- UI очищает отклонённую строку из списка и показывает подтверждение. История сохранена в журнале.
- Таблица сохраняет P19-D колонку «Время» и контекстные подсказки. Действие «Применить» остаётся в колонке 6; «Не применять» добавлено в колонку 7. Только smoke P19-D, проверявший число столбцов и заголовки, адаптирован под 8 столбцов.

## Пять сценариев ручной проверки Windows

1. Открой «Настройки → Конвертация → Ожидают применения»: справа от «Применить» расположена кнопка **«Не применять»**. При отсутствии событий очередь пуста — **не совершай реальный донат ради теста**: заполненные сценарии проверены в временной SQLite базе.
2. Кнопка доступна и для события без курса, когда «Применить» заблокирована. В диалоге проверь источник/игру/ID/сумму и предупреждение «без начисления» и необратимость.
3. Нажми **«Нет»** в диалоге — строка не исчезает, начисление/состояние не меняются. Если действительно есть ненужное событие, можно подтвердить **«Да»** — только оно исчезнет из очереди, а баллы никуда не начислятся. Не отклоняй реальные нужные события ради проверки.
4. После отклонения F5, смена курсов и перезапуск не возвращают событие в очередь. Исходное событие и действие \`reject_pending\` сохраняются в журнале. Автотест также проверяет дубли провайдера, повторный Apply/Reject и откат транзакции.
5. Проверь минимальную ширину окна, F5, вкладки и OBS/аукцион/таймер/колесо. Прежние правила начисления кнопкой «Применить» не изменились; отвергнутые события не влияют на аукцион.

Автотест \`tools/conversion_pending_no_apply_smoke.py\` (пять сценариев): no-rate rejection; durable audit and no credit; later-rate persistence and replay dedup; SQLite trigger atomic rollback; Qt Yes/No; unchanged source auction. Проходят прежние P19-B/C/D и все штатные Windows regressions.
