# P21-A / UI-087 — последовательные лоты «Без текста N» для пустого внешнего сообщения

**Только отдельный Windows QA, не принято пользователем, не объединять с `main` до ручной проверки.** Источник согласованных требований — `docs/ACTIVE_REVIEW_LEDGER.md`, UI-087, решение от 2026-10-06; дополнительное прямое уточнение пользователя от 2026-10-21 о самостоятельном переименовании лотов **между** аукционами. Не добавлять неутверждённых правил совпадения названий.

## Узкая реализация

- Изменена только ветка **accepted normalized external event с пустым после trim сообщением**, **без явно указанного `game_id`**, принадлежащего конкретной **running** auction session. Уже определённый лот `game_id` и обычный непустой текст остаются на прежнем B3 пути. Пустой target **вне** running auction по-прежнему `missing_target`, без автоматического создания списка.
- В каждом запущенном аукционе такие принятые события получают `Без текста 1`, `Без текста 2`, `Без текста 3`, ...; новый аукцион начинает снова с 1. Счётчик берётся из неизменяемых `external_events.payload_json.normalized.generated_blank_auction_id/generated_blank_number`, а не из текущего названия; после ручного переименования или отклонения pending номер никогда не освобождается. Оригинальный `normalized.lot_title` остаётся пустым (как пришёл), аудиторская metadata не меняется.
- Проверка дубликата `source+external_event_id` срабатывает **до** выделения нового номера и создания лота. Повторная доставка не добавляет новый лот и не начисляет повторно.
- При известном курсе новый номер поступает в тот же принятый `_add_or_increment_auction_lot_conn` для зачисления exactly once и появления лота в аукционе. При неизвестном курсе этот же метод вызывается с 0 баллов, чтобы лот стал видимым сразу, а `pending_conversions` содержит **конкретные `game_id` + `auction_id`**; после явного сохранения курса и `Применить` начисление производится тому же лоту. `Не применять` оставляет исходные audit и порядковый номер, без баллов.
- **Пользователь прямо отказался от дополнительной автоматики совпадений между аукционами.** Обычный B3 title-normalization / existing-title merge **не изменён** ни для обычных, ни для служебных названий. Поэтому не переименованный после предыдущего аукциона постоянный `Без текста 1` может быть выбран при совпадении в новой сессии: пользователь самостоятельно редактирует записи между аукционами. Ни новые суффиксы, ни специальные обходы поиска, ни запрет повторных названий не вводятся.
- Не менялись ставка/баллы для непустых сообщений, статус аукциона, колесо/таймер/OBS/звук, SQLite schema/migrations или программа 1.0.8. Публичный релиз не выпускать.

## Автоматические проверки

`tools/integration_blank_message_auction_smoke.py`:

1. Три последовательных RUB events с известным курсом создают три исходных лота `Без текста 1..3`, разные IDs, 3 contributions, неизменённую оригинальную пустую строку и provider metadata; duplicate одного event не меняет counters.
2. Неизвестная unit создаёт видимый `Без текста 1` с нулевым начислением и session-scoped pending; новый следующий event идёт в `Без текста 2`; после сохранения курса **только явное Apply** начисляет в прежний game_id.
3. После ручного переименования и `Не применять` последующий event получает следующий номер, не переиспользуя прежний.
4. Пустое внеаукционное сообщение осталось `missing_target`, непустой target остался по прежнему matching.
5. Нумерация нового аукциона снова с 1; специально проверяется, что существующий persistent `Без текста 1` может быть выбран по неизменённым правилам совпадения. Это **явно принятая пользователем ответственность**, а не баг в тесте.

Кроме отдельного P21-A Windows шага обязателен полный Regression Foundation 1.0.8: P20-A–M, real Qt, OBS/Chromium, Inno Setup, silent installed start, Publication wording gate.

## Ручная проверка

1. Установить точный P21-A QA поверх существующей 1.0.8; игры, настройки, интеграции, OBS, музыка на месте; F5 и компактный интерфейс не изменены.
2. При наличии подключённой интеграции и **реального** поступления без сообщения во время аукциона, появится `Без текста 1`; следующее отдельное событие без текста — `Без текста 2`. Не отправлять реальные донаты специально ради QA — это покрывается тестами.
3. Непустое сообщение со знакомым/новым названием обрабатывается **по-прежнему**. Внеаукционное пустое сообщение не создаёт лот.
4. Неизвестный курс: служебный лот виден, но без баллов; `Настройки → Конвертация` содержит pending с исходным названием `Без текста N`. После сохранения курса баллы **не начисляются сами** — нужно `Применить`, либо `Не применять`. При необработанных событиях UI-086 warning/gate активен.
5. Сохранить/переименовать созданные лоты обычными принятыми средствами между аукционами. В новой сессии нумерация снова с 1. Если прежние названия оставлены, старое правило совпадений не изменяется — новая автоматика их не исправляет.
6. Проверить минимальную ширину, историю лотов, вкладку `Список`, колесо, таймер, OBS и музыку, отсутствие неожиданной смены вкладок и настроек.
