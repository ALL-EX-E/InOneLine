## Изолированные изменения

1. Карточка Twitch-наград сохраняет несохранённые изменения **в памяти UI**, если происходит пересоздание карточек (обычный переход между страницами настроек, принудительный refresh, получение нового состояния подключения / scopes). Сохраняются общее название, число/стоимость строк, цвет, зарегистрированные reward IDs. Сравнение с последней реально сохранённой конфигурацией; возврат к исходному тексту очищает dirty-state. Обычная навигация **не пишет** в SQLite, не вызывает Twitch API.
2. При явной смене/удалении подключения Twitch с изменённым черновиком требуется подтверждение сброса. Отмена оставляет данные и не начинает переподключение. При неудаче самой операции черновик остаётся; успешная смена не переносит награды предыдущего аккаунта.
3. Удаление зарегистрированных наград — отдельное подтверждаемое удалённое действие. При наличии несохранённых изменений предупреждение сообщает, что они будут сброшены **только при успешном удалении**. Реальное удаление никуда не переносится и не инициируется автоматически.
4. `Сохранить и синхронизировать награды`: до изменения локальных настроек проверяется локальная корректность конфигурации и авторизация/возможность управления наградами через существующий `ensure_manage_scope`. Во время запущенной синхронизации редакторы блокируются, в том числе при перестроении страницы.
5. Затем локальная конфигурация сохраняется, и выполняется прежняя Twitch sync. Если Twitch ошибается после локального сохранения, пользователь видит **«Настройки наград сохранены в программе, но синхронизация с Twitch не завершена»** и предупреждение о возможном частичном обновлении удалённой стороны, с возможностью повторить действие. НЕ обещаем откат, не выполняем опасную компенсацию remote reward mutations.
6. При успешной синхронизации карточка считывает реальные сохранённые Reward ID, полученные от Twitch, вместо наложения устаревшего unsaved UI-чeрновика. Иные действия (проверка статуса, подтверждение scope, обычное включение и выключение наград) сохраняют пользовательский черновик.

Архитектура: только `streaming_manager/views/settings.py`, отдельный Qt smoke `tools/twitch_reward_draft_sync_smoke.py`, Windows CI и эта запись. Без схемы/нового хранилища, без изменений adapter, EventSub, начислений, колеса, таймеров и истории.

## Контроль

Windows smoke: переход по настройкам сохраняет dirty-поля без записи в DB; прямой refresh; отмена/явное подтверждение переподключения; невалидный черновик и failed preflight не пишут настройки; partial-sync сообщает локально сохранено + Twitch не завершён; successful-sync перечитывает real Reward ID.

Ручная установленная сборка — **5 проверок, последовательно**:
1. Ввести/изменить название, стоимость, цвет, добавить строку; перейти между вкладками; убедиться, что изменения сохранились **в UI**, но не в постоянном хранилище.
2. Вызывать обычное обновление статуса Twitch; черновик сохраняется; при сохранённом реальном ID и переходе не теряется.
3. Невалидная конфигурация не сохраняется; при проблемах подключения до preflight не изменяет БД; не требуется специально менять права аккаунта.
4. При ошибке remote sync только после local stage текст честно сообщает, что локальная конфигурация сохранена, Twitch — не синхронизирован; сценарий тестируется автоматикой и не требует специально создавать provider failure на живом Twitch.
5. Регрессия существующих ID, включения наград, независимости DonationAlerts, истории, колеса и перезапуска.
