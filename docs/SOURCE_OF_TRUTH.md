# Source of truth

## Канонический источник

Начиная с **2026-09-30** канонический источник проектного состояния InOneLine — публичный GitHub-репозиторий `ALL-EX-E/InOneLine`.

Google Drive после этой границы используется только как дополнительный резерв/исторический архив и не должен определять текущее состояние проекта.

## Иерархия

При обычном продолжении разработки использовать в таком порядке:

1. `docs/PROJECT_STATE.md`
2. `docs/ROADMAP.md`
3. `docs/DECISIONS.md`
4. `docs/WORKFLOW.md`
5. release notes, Git tags/Releases и фактический код текущего `main`
6. документы `docs/history` — только для исторического контекста

Если сведения конфликтуют, более новое прямое решение пользователя должно быть записано в канонические документы и после этого становится авторитетным. Старые исторические блоки не получают приоритет только потому, что содержат слова `CURRENT`, `APPROVED` или `USER ACCEPTED`.

## Что хранится где

- Код и текущая документация — Git repository.
- Официальные installer/source релизы — GitHub Releases.
- Candidate build artifacts — GitHub Actions; они временные и не являются долговременным архивом.
- Google Drive — резерв старых документов/промежуточных сборок, но не источник текущей истины.
- Credentials, tokens, secrets, пользовательские базы и приватные данные не публикуются в публичном репозитории.

## Обязательное правило после рабочего чата

Если в чате принято долговременное решение, изменён roadmap, закрыт QA или изменён CURRENT, соответствующий GitHub-документ должен быть обновлён в рамках той же рабочей линии. Нельзя оставлять существенное решение только в чате.
