# P18-F / UI-084 — понятные формулировки интеграций и локальное время

Дата: 2026-10-18. Основа: вручную принятый P18-E, точный проверочный Git tree `4a942b298f44e40d49fc62c734277e9e756cc01f`. Реализация только после подтверждения переноса P18-E в `main`.

## Границы изменения

- Сохраняется внешний карточный интерфейс `Настройки → Интеграции`, старые операции, привязки кнопок, защищённое хранилище, протоколы Twitch/DonationAlerts и архитектура источников событий.
- Вместо технических описаний публичной авторизации показываются понятные пояснения о входе Twitch и DonationAlerts, не требующем передачи программе пароля или Client Secret.
- Список возможностей и детали о канале/аккаунте переводятся только в **представлении карточки**. Исходные значения `adapter.capabilities` и идентификаторы provider/permission не меняются.
- `Права B4` → `Права на управление наградами`; `DonationAlerts User ID` → `ID пользователя DonationAlerts`; `Centrifugo WebSocket` → `События DonationAlerts в реальном времени` в обычном UI; названия протоколов остаются в коде/diagnostics, где необходимы.
- `Последняя проверка` и `Последняя принятая активность` используют **имеющуюся общую** `display_datetime_local` из `streaming_manager.database`. Не меняются SQLite timestamps UTC, данные истории, backend, timezone Windows или отдельные статусные окна аукциона.
- Дополнительных миграций, таблиц, нового хранилища состояния, изменений Twitch/DonationAlerts API и нового механизма форматирования даты нет.

Файлы: `streaming_manager/views/settings.py`, `tools/integration_copy_local_time_smoke.py`, регистрация smoke в Windows regression workflow, этот QA-документ.

## Пять отдельных пунктов ручной проверки (Windows)

1. Открыть `Настройки → Интеграции → Twitch`. Описание входа должно быть понятным по-русски; технической строки Device Code Grant Flow / Public client нет. Данные авторизации и пароль описаны корректно. Прежние кнопки остаются работоспособны.
2. В карточке DonationAlerts описание входа и защищённого хранения понятно; доступные возможности показывают `события ... в реальном времени` и историю пожертвований, а не `Centrifugo WebSocket`. Для встроенного приложения не предлагается ручная настройка ID.
3. Если уже подключены сервисы, поля канала, `Права на управление наградами` и `ID пользователя DonationAlerts` отображаются корректно. Если сервис не подключён, достаточно проверить русские названия возможностей, не выполняя авторизацию ради QA.
4. При существующих событиях/проверках поля `Последняя проверка` и `Последняя принятая активность` используют формат `ДД.ММ.ГГГГ ЧЧ:ММ:СС` местного часового пояса Windows, без raw ISO/UTC `T...+00:00`. При отсутствии событий время не выдумывается; инъекция UTC→local отдельно проверена автоматическим smoke.
5. Переключить вкладки, вызвать F5, перезапустить приложение и проверить, что подключение, история, Twitch reward draft, RANDOM.ORG API-ключ, аукцион и OBS ведут себя как раньше; никакие даты и credentials не были изменены только из-за отображения.

Автоматический Qt smoke `tools/integration_copy_local_time_smoke.py` проверяет оба провайдера без сетевых действий, русские видимые строки, сохранность структур capability и UTC в БД, состояние кнопок и повторное построение карточек.
