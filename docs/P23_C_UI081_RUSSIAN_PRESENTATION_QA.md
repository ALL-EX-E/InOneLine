**Отдельный QA-кандидат. Не объединять с main до ручного Windows PASS.**

## Утверждённый объём

Третий пункт UI-081 из ACTIVE_REVIEW_LEDGER: технические entity/action и сведения в журнале отображаются понятнее, при сохранении authoritative `change_log`. Для аукционных записей использовать существующий `format_auction_history_event`, для полных успешных интеграционных начислений — `format_integration_bet_event`; прежний game formatter не дублировать. Для известных настроек показывать ключ и старое/новое значение, с обязательной защитой секретов; конвертации — через безопасные поля. Неизвестные типы/действия имеют технический fallback без потери данных. Не создавать второй audit backend/DB/SQL, не менять хранилище, схему, миграции, версию, таймеры, колесо, интеграции, OBS или публикацию.

## Автоматическая регрессия

`tools/journal_russian_presentation_smoke.py`: реальный Qt LogTab, русский вид истории аукциона, настройка и сокрытие токенов, интеграция/конвертация, игры, unknown fallback, 500-row/full-search, технический и русский поиск, старые 5 колонок/debounce. Полная нативная Windows Regression Foundation + Publication wording gate обязательны.

## Ручная проверка Windows

1. Установить ровно QA ZIP поверх принятой 1.0.8. Проверить, что список, база, настройки и история сохранились.
2. Во вкладке «Журнал» убедиться, что объект «Аукцион», «Ставка», «Лот аукциона» и распространённые действия/подробности отображаются на русском.
3. Создать тестовый аукцион, изменять баллы и остановить/продолжить таймер: события понятны и согласованы с «Историей аукционов».
4. Проверить события игры и настройки (видны старое/новое значение; секреты/токены не раскрываются).
5. Проверить интеграционные события/конвертации там, где они уже имеются: источник, начисление/причина/получатель; нет сырых Python-словарей в типовых случаях.
6. Проверить поиск по русскому описанию и техническому action/ID, очистку поиска, последние 500 строк и F5.
7. Проверить смену вкладок, OBS, Музыку и «Историю аукционов»: прежняя логика без изменений.
