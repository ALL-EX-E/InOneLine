# P20-C / UI-086 — новый title-only лот исходного аукциона после 00:00

**Изолированный кандидат QA, не принят и не слит.** Версия 1.0.8, схема SQLite и установочный путь прежние. Основан на уже вручную принятом P20-B FIX1; до завершения promotion #291 цель PR — его проверенная ветка, затем main.

## Граница изменения

Если внешнее событие поступило **во время исходного аукциона Max Amount** и осталось ожидающим конвертации, после 00:00 оператор может явно применить событие к сохранённому `pending_conversions.auction_id`, даже когда сохранённого названия ещё не было среди лотов сессии. Исходный аукцион должен оставаться предварительным (`winner_selected` или `tie_break_required`); никаких новых сессий/переназначений и автоматического применения.

- Используется точное нормализованное `lot_title` из неизменяемого `external_events.payload_json`. Только событие без `game_id` может добавлять отсутствующий title-only лот.
- Если постоянная неархивная игра с таким названием уже существует вне стартового набора, она включается в исходный аукцион без копии. Полностью новое название создаёт временную `auction_only=1` игру и исторический снимок `auction_entries`.
- Удалённый временный лот (`game_id=NULL` и совпадающий snapshot_title) не воссоздаётся; архивные и чужие временные игры также не используются.
- Создание/поиск лота, баллы игры, ставка/вес исходной сессии, contribution, событие, pending и audit сохраняются атомарно через уже существующий `apply_pending_conversion_event`; повторный event ID не начисляется.
- Предварительный победитель/ничья пересчитывается по выжившим лотам, а истёкший таймер, источник, wheel_spin_id, finished_at, deadline_at и confirmed/cancelled история не меняются.
- Операция «Не применять» и блокировка подтверждения результата при других неразрешённых событиях остаются.
- **Не входит в P20-C:** новые фактически поступившие ставки после 00:00 (их отдельное правило), свободное ручное добавление лотов после 00:00, общий weighted-wheel freeze, stop/cancel warnings, исправление старой метки `finish_auction` для удалённого лота.

## Автоматические проверки

`tools/auction_pending_post_expiry_new_title_smoke.py` — 5 реальных SQLite-сценариев без пользовательской базы:

1. Новый title-only лот создаётся в исходном аукционе, выигрывает и не запускает таймер.
2. Постоянная игра по названию повторно используется, без дублирования и с созданием ничьей.
3. Историческая запись удалённого временного лота остаётся удалённой, ожидающее событие не списывается.
4. Подтверждённая сессия остаётся неизменной и не переносит поступление в следующую.
5. Новый лот формирует ничью, повторная доставка того же event ID не начисляется.

В полном Windows CI остаются все P20-A, P20-B, FIX1, UI, OBS, Chromium и installer тесты; отдельный wording gate обязателен.

## Ручная проверка на Windows

1. Установи именно P20-C QA, проверь запуск, сохранность данных и F5.
2. Открой «Настройки → Конвертация», «Аукцион → Проведение». Обычные таймер, музыка и OBS не изменены.
3. При наличии настоящего ожидающего поступления, которое изначально относилось к этому Max Amount до 00:00 и содержит новое название, после 00:00 проверь кнопку «Применить»: создан/подключён только исходный лот, баллы и предварительный исход обновлены, таймер остаётся 00:00, дубли невозможны.
4. Если события нет — не создавай платёж ради QA; новые сценарии проверяются изолированными автоматическими тестами.
5. Для подтверждённого/закрытого аукциона новая title-only цель не должна создавать лот; удалённые лоты не восстанавливаются.
