# P19-F / UI-085 — сохранение несохранённых курсов при изменении интеграций

Изолированный пункт #7 из UI-085 после принятого пользователем P19-E. Версия 1.0.8. **Черновик QA — не принято, не сливать в main, не выпускать официальный релиз.**

## Изменения

- Ранее вкладка \`Настройки → Конвертация\` пересоздавала поля при изменении набора единиц/подключений и могла потерять **несохранённый** текст. Для каждого нормализованного ключа единицы ведётся **только оперативная UI-карта** несохранённых значений, в памяти открытого окна.
- При любой перестройке набора строк (подключение, отключение, переподключение, изменение возможностей адаптера, принудительное обновление отображения) изменённые значения восстанавливаются по тем же ключам. Скрытое поле специфической единицы сохраняет свой черновик в памяти, пока адаптер отключён; при повторном подключении текст появляется снова.
- Новый видимый ввод берёт значения из БД по прежним правилам. Пока пользователь явно не нажал **«Сохранить курсы»**, ни черновик, ни отключение не сохраняют его в SQLite. Несохранённое значение исчезает **после закрытия программы**, и об этом явно сказано в интерфейсе.
- Успешное атомарное сохранение существующим методом \`set_conversion_rates_atomic\` сбрасывает **только черновики видимых сохранённых полей**; скрытый черновик сохраняется до переподключения. При ошибке проверки поля и несохранённые тексты остаются без изменений. Если вернуть значение поля к сохранённому, запись о черновике автоматически убирается.
- Действующие политики UI-084/Twitch reward draft и поведения Google/OBS/аукциона не меняются; API, схема SQLite, расчёт ставок и обработка событий не затрагиваются. Отложенные сервисные курсы в SQLite при отключении интеграции сохраняются как раньше.

## Пять сценариев ручной Windows-проверки

1. В \`Настройки → Конвертация\` введи новое значение курса (например, RUB), но **не нажимай «Сохранить курсы»**. Перейди на другую вкладку «Настройки» и обратно, а также нажми F5. Черновой текст должен остаться; сохранённый курс пока не меняется.
2. Если у тебя реально подключена интеграция с собственной единицей (например, Twitch channel points), измени её курс **без сохранения**; отключи/подключи интеграцию обычными кнопками. Исчезнувшее поле возвращается с прежним **несохранённым** текстом. Если такой интеграции нет, не подключай её ради проверки: UI-перестройки покрыты пятью изолированными Qt-тестами.
3. При появлении или исчезновении другой валюты ранее изменённое видимое поле RUB не должно очищаться или сбрасываться. При отключённом сервисе скрытые значения **не записываются** в SQLite, даже если нажать «Сохранить курсы» для остальных видимых курсов.
4. Проверь сохранение валидных курсов: после нажатия «Сохранить курсы» поля принимают нормализованные значения, после перезапуска они сохраняются. Ошибка в одном поле должна блокировать всю запись и оставить **все** черновики. Менять реальные курсы без необходимости не нужно; исходные параметры после теста восстанови.
5. Проверь минимальную ширину окна, вкладки, F5, конвертацию ожидающих событий, кнопку «Не применять», OBS и аукцион. Черновики не должны сами начислять баллы или менять правила обработки входящих событий.

Native \`tools/conversion_rate_draft_preservation_smoke.py\` покрывает пять сценариев: скрытый/видимый draft через disconnect/reconnect и force-refresh; сохранение только видимых полей; новый capability/currency; сохранность после ошибки валидации; отмена draft возвратом к сохранённому. Существующие Windows P19-A/B/C/D/E и общие OBS/gui/timer/install тесты остаются включены.
