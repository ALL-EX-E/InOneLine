**Стадия:** отдельный **QA-кандидат на ручную проверку**, НЕ публичный релиз и НЕ замена CURRENT.
**Основание:** утверждённый порядок `docs/ACTIVE_REVIEW_LEDGER.md` §4.7 «FINAL GATE», после пользовательской приёмки P23-C/UI-081 №3.
**Обязательный порядок:** 1) user PASS UI-081 №3 → exact-four-blob promotion → fresh Windows CI → independent main postmerge CI; 2) FINAL GATE validation-only candidate + полная Windows CI + публикационный wording gate; 3) ZIP SHA256/CRC и архив в существующей Google Drive QA-папке; 4) независимая **ручная** приёмка всех сценариев; 5) только после отдельного разрешения пользователя возможна замена CURRENT/выпуск.

## Область FINAL GATE — исключительно проверка

- Никаких изменений в `app.py`, `streaming_manager/**`, базах, схеме, миграциях, алгоритмах аукциона, интеграциях и компонентах OBS.
- `APP_VERSION = 1.0.8`, `SCHEMA_VERSION = 19`, **15** именованных миграций. На этапе QA **не** менять эти значения, не создавать релиз, не запускать публикацию.
- Уже существующая `Regression Foundation 1.0.8` в Windows включает PySide6/Qt, свежую SQLite, все промежуточные целевые smoke, OBS/Chromium, backup/restore, миграции, frozen PyInstaller, Inno Setup и silent installer startup.
- Mechanical coverage audit: в `tools/` имеется 68 самостоятельных `*_smoke.py`; 67 исполняются напрямую общей регрессией, **один** `position_policy_smoke.py` ранее выполнялся только косвенно/не вызывался напрямую. FINAL GATE добавляет именно его как отдельный native Windows шаг; таким образом все 68 запускаются непосредственно. Проверить динамическим сравнением `tools/*_smoke.py` с вызовами `python tools/...smoke.py` в workflow. Не переписывать тесты ради прохождения.
- Границы видимости: не обещать полный реальный Twitch/DonationAlerts/YouTube без подключённых аккаунтов. Для них обязательны существующие simulation/native tests и доступные авторизованные интеграционные сценарии. Не ставить токены/секреты в общедоступный журнал.

## Лист сквозной ручной Windows QA

Выполнять на изолированной тестовой копии, сохранив внешний `.iolbackup` и оригинальные медиа перед любыми разрушительными операциями.

1. **Сверка кандидата:** установить ТОЛЬКО архив FINAL GATE с зафиксированными URL/ZIP размером/SHA256; проверить `InOneLine_Setup_1.0.8.exe`, запуск, версию 1.0.8. Не подменять сборкой из другого PR.
2. **Чистая установка:** на чистом тестовом пути установить и запустить программу; папки/иконка/ярлыки соответствуют CURRENT. Работает без установленного Python/IDE, не появляются лишние каталоги.
3. **Обновление поверх 1.0.8:** повторно установить в прежний выбранный каталог с тестовой существующей базой; сохранились все игры, баллы, архив, история, настройки, музыка, управляемые медиа, `ui_state.ini` и резервные копии.
4. **Резервные копии:** создать `.iolbackup` вне каталога программы; в отдельной тестовой среде восстановить его, проверить содержимое и отказ/rollback при некорректном архиве. Не восстанавливать экспериментальные данные поверх рабочих.
5. **Список/CSV:** добавить, изменить, найти, фильтровать и архивировать тестовую игру; проверить статус/баллы, импорт CSV с валидными и ошибочными датами, поведение безопасного отказа, отмену диалога удаления.
6. **Публичный список и XLSX:** проверить экспорт/импорт/публичный источник, порядок и колонки позиций, отсутствие неожиданной потери игр и конфигурации, корректное обновление.
7. **Стрим / OBS:** проверить URL виджетов, копирование/предпросмотр браузер-источников, игровые карточки, фон GIF/видео/изображение, показ/скрытие, внешний вид на основном 2560×1440 и минимальном окне. При исчезновении исходника — предсказуемая обработка без краха приложения.
8. **Правила и шаблоны:** выбрать неактивный шаблон — предпросмотр показывает выбор, эфир остаётся на активном; активировать другой во время тестового аукциона — эфир обновляется; после активации предпросмотр снова следует последующим выборам, не «залипает».
9. **Музыка / OBS-звук:** проверить вывод через программу, через OBS Browser Page при выключенном «Управление аудио через OBS» и через OBS-микшер при включённом. Не считать отсутствие локального звука без мониторинга OBS дефектом.
10. **Максимальная сумма:** создать аукцион, лоты и ставки; старт/пауза/продолжение/коррекция времени/сброс; предсказуемое автопродление, точные баллы и отсутствие повторных начислений.
11. **Аукцион после 00:00:** в Max Amount вручную добавить/уменьшить баллы, создать/переиспользовать/переименовать/удалить временный лот, исключить постоянный лот, проверить запрет возрождения удалённого и сохранение постоянных игр; таймер не должен сам запускаться заново.
12. **Ничья / колесо:** проверить дополнительное время, переход к обычному/взвешенному колесу, таймер от 1 секунды, обычный и режим выбывания, «Стоп»/сохранённый результат/повтор анимации без нового определения победителя. Состав и веса после «Провести колесо» заморожены.
13. **Ожидающие конвертации:** смоделировать поступление до и после 00:00 в исходный аукцион, незаданный курс, ручное «Применить» / «Не применять», точно-однократное начисление, защиту необратимого закрытия и неизменность уже завершённой истории. Отказ не должен начислять баллы.
14. **Пустое сообщение / интеграция:** проверить последовательные `Без текста N` для разных событий во время аукциона и подавление дублей одного provider event, правильный источник/цель, безопасное завершение/отмену с предупреждением.
15. **История / Журнал:** хронологическая сортировка истории, реальный путь определения победителя и условная вкладка верификации; в «Журнале» тёмные чередующиеся строки, русские имена объектов/действий, понятные подробности, поиск по русскому и оригинальному техническому action/ID, очистка поиска, F5 и 500 последних событий без фильтра.
16. **Окна и сохранение:** компактная разметка при минимальном размере, отсутствие наложений, сохранение цветов/шрифтов/позиции окна после перезапуска, повторный запуск единственного экземпляра, нормальное завершение без ошибок.
17. **Установка/удаление на отдельной копии (деструктивный пункт):** проверить предупреждение удаления и возможность безопасной отмены. Полное удаление тестового экземпляра допустимо только после отдельного `.iolbackup`; внешний бэкап и внешние файлы не затрагиваются. Никогда не удалять рабочий экземпляр для проверки.

## Критерии приёмки

- Все native Windows regression steps, frozen startup, silent-install, backup/restore, integration simulation и Publication wording gate **SUCCESS** на точном FINAL GATE source HEAD.
- Один точный GitHub Actions installer artifact → проверенный ZIP SHA256/CRC → один файл в согласованной QA-папке Google Drive. Не путать ZIP самого Actions с лежащим в нём `.exe`.
- По каждому ручному пункту пользователь подтверждает PASS. При FAIL записать воспроизведение, код не объединять/не выпускать, исправление отдельно согласовать.
- **Финальное разрешение на публикацию не вытекает автоматически из PASS.** Требуется отдельная команда пользователя. QA-1.0.8-01/-02 — вне утверждённого пакета.
