# P19-D / UI-085 — местное время внешнего события в очереди конвертации

Основа: вручную принятый P19-C / UI-085 (пользователь 2026-10-19 подтвердил «Всё работает. Идём дальше.»), exact-tested promotion PR #271. Изолированный следующий пункт #5 из ACTIVE_REVIEW_LEDGER. Версия остаётся 1.0.8; официального релиза нет.

## Область изменения

- В таблице `Настройки → Конвертация → Ожидают применения` добавить колонку **«Время»** между «Источник» и «Событие». Показывать локальные `ДД.ММ.ГГГГ ЧЧ:ММ:СС` стандартной функцией `display_datetime_local`, уже используемой в «Интеграции».
- Отображаемое время берётся из `external_events.created_at` (`event_created_at` во view модели), а не из времени постановки в очередь `pending_conversions.created_at`. Оба поля остаются исходными UTC значениями SQLite без UPDATE, миграции и коррекции локального часового пояса в базе.
- Tooltip каждой ячейки (и кнопки «Применить») показывает контекст: источник, contributor, external event ID, название цели и привязку к исходному аукциону, если она есть. Полный технический аудит остаётся в `Журнал`, без добавления новых видимых столбцов.
- Из-за новой колонки индекс существующего действия «Применить» меняется с 5 на 6; существующие P19-C UI-тесты обновлены только по ожидаемым индексам.
- Не менять пересчёт валют, атомарное сохранение, `can_apply`, обработку новых названий игр, автоматическое начисление, source-auction политику, провайдеры, таймер, колесо, историю, OBS, SQLite schema или настройки.

## Ручная проверка Windows (пять сценариев)

1. Установи P19-D Windows QA поверх предыдущей версии, открой `Настройки → Конвертация → Ожидают применения`. У таблицы должна быть колонка «Время» сразу после «Источник». Если очередь пуста — не создавай реальный донат ради теста: обязательная проверка заполненных данных выполняется в временной SQLite базе.
2. Для существующего события время должно быть местным временем Windows (`ДД.ММ.ГГГГ ЧЧ:ММ:СС`), а не сырым ISO UTC. Автотест специально различает время внешнего события и время попадания в очередь, чтобы исключить ошибочный источник.
3. Наведи курсор на любую ячейку строки или кнопку «Применить». Должна появиться подсказка с источником, отправителем, ID внешнего события, игрой и идентификатором исходного аукциона, если событие от него.
4. Сохранение курса по-прежнему только обновляет расчёт/доступность кнопки «Применить»; начисление без явного подтверждения отсутствует. P19-C title fallback и вся защита от чужих/закрытых аукционов сохранены. Не нажимай «Применить» для реального события, если начисление не требуется.
5. Проверь F5, переходы между вкладками, повторный запуск и минимальную ширину окна: колонки и подсказки доступны, список не накладывается на другие элементы. Интеграции, аукцион, колесо, история и OBS работают как раньше.

Тест `tools/conversion_pending_event_time_smoke.py` проверяет три независимых сценария: правильный источник UTC/local presentation при несовпадающих timestamps; tooltip с provenance и source-auction ID; обновление расчёта/кнопки без автокредита, с прежним временем события. Существующие P19-C tests тоже выполняются.
