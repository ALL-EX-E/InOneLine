# P22-B / UI-080 — история завершённых аукционов: только полезная сортировка по дате

**Отдельный QA-кандидат, не принят пользователем и не объединён с `main`.** Первый ограниченный шаг уже утверждённого UI-080 из `docs/ACTIVE_REVIEW_LEDGER.md`: убрать сортировку по автоматически созданным названиям аукционов.

## Изменение
- В существующей вкладке `История аукционов` у `QComboBox` сортировки оставить ровно `Новые → старые` и `Старые → новые`. По умолчанию — `Новые → старые`.
- Убрать недоступные теперь варианты `Название А → Я` / `Название Я → А` и только соответствующие устаревшие ветки SQL `name_asc/name_desc`. Ссылка на эти коды найдена лишь в двух исходных файлах (view и DB); fallback остаётся `newest`.
- Не менять запросы по периоду, поиску, summary, read-only/detail, pagination `50 + Загрузить ещё`, исторический `lot_count`, audit, verification snapshots и сохранённые аукционные данные.
- Не реализовывать одновременно остальные пункты UI-080: фактическую цепочку режимов, условную вкладку проверки, расширение форматирования событий. UI-081 (Журнал) тоже отдельно.
- Никаких изменений версии 1.0.8, схемы SQLite, бизнес-логики, RNG, OBS, интеграций и релиза.

## Автоматические проверки
`tools/completed_auction_history_sort_smoke.py`:
1. В списке сортировок ровно два утверждённых текста/кода, порядок по умолчанию newest и переключение oldest работает.
2. Дата, а не лексикографическое имя `Аукцион #N`, определяет порядок.
3. SQL-пагинация, поиск по аукциону, фильтр периода и summary не исчезают.
4. Детальные read-only страницы `Общие / Лоты / События` остаются.

Обязателен полный Windows Regression Foundation 1.0.8 (включая P22-A), Publication wording, Inno Setup + silent startup, OBS/Chromium.

## Ручная проверка
1. Установить точный P22-B Windows QA поверх существующей 1.0.8. Список игр, настройки, интеграции и история сохраняются.
2. Открыть `История аукционов`: в выпадающей сортировке ровно два пункта — `Новые → старые` и `Старые → новые`; вариантов `Название А/Я` больше нет.
3. Переключить обе сортировки при нескольких завершённых сессиях: по умолчанию новые сверху, второй вариант — старые сверху; номера вроде `#9 / #10` не сбивают порядок.
4. Проверить поиск по аукциону/ID/лоту, периоды, счётчики и `Загрузить ещё` при наличии более 50 историй.
5. Открыть завершённую сессию: вкладки `Общие`, `Лоты`, `События`, `Проверка результата` работают как до изменения.
6. Проверить F5 и узкое окно. Не должно быть изменений в аукционе, OBS, музыке и общем Журнале.

После нативных Windows+wording SUCCESS — проверенный SHA256/CRC QA ZIP на Google Диске и явная ручная приёмка. Лишь затем переносить точно проверенные Git blobs в `main` и запускать postmerge CI.
