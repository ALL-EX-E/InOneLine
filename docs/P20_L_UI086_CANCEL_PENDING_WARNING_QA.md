# P20-L / UI-086 — предупреждение при остановке аукциона с ожидающими поступлениями

**Изолированный Windows QA-кандидат. Не принят пользователем, не объединять с main до ручной проверки.** Следует после принятого P20-K. Основание — ранее утверждённый UI-086: отдельное предупреждение при stop/cancel в случае неразрешённых событий исходного аукциона. Отдельной задачи «переименовать постоянные лоты» в утверждённой дорожной карте нет; она не реализуется.

## Границы изменения

- Только при нажатии существующей кнопки **«Остановить аукцион»** читается принятый ранее счётчик `db.count_unresolved_auction_conversions(session.id)` для **текущей** исходной сессии. Он учитывает исключительно `awaiting_rate` и `awaiting_manual_apply` из `pending_conversions` с совпадающим `auction_id`. Чужие аукционы и внешние события вне аукциона не считаются.
- При количестве больше нуля существующий диалог подтверждения остаётся тем же (в том числе разные принятые тексты отмены после выбора победителя и режима на выбывание), но к его сообщению добавляется заметное предупреждение с точным количеством. В тексте сказано, что остановка **не применит и не отклонит** pending автоматически, что после отмены они не исправят результат исходного аукциона и что для обработки **до остановки** нужно выбрать **«Нет»** и открыть **«Настройки → Конвертация → Ожидают применения»**.
- При количестве ноль текст, кнопки и поведение старого подтверждения не меняются. **«Нет»** остаётся выбором по умолчанию. Закрытие диалога или отказ оставляет сессию и pending без изменений.
- При осознанном **«Да»** вызывается **исходный** `db.cancel_auction`, без изменений БД/политики. Pending не зачисляются и не отклоняются автоматически; их существующие записи и исходное событие сохраняются. Отменённый аукцион не открывается заново и не пересчитывается. Никакой новой команды миграции/изменения баллов не добавляется.
- Если счётчик не удалось получить, операция прекращается с существующим диалогом ошибки; не выполняется неподтверждённая остановка.
- **Не входит:** блокировка остановки, новые правила обработки событий после отмены, Max Amount → Wheel freeze и любые изменения колеса/таймера/OBS/музыки, ставки/баллы, переименование лотов, изменения схемы SQLite. Версия 1.0.8.

## Автоматические Windows Qt/SQLite проверки

Четыре новых `test_cancel_auction_*` сценария добавлены к `tools/auction_pending_result_gate_smoke.py`. Полный P20-A–K набор остаётся, плюс самостоятельный P20-L CI шаг:

1. Исходный аукцион с одним собственным pending и чужими pending: диалог показывает **1**, путь Конвертации и default «Нет»; отказ сохраняет сессию, pending и баллы.
2. Остановка с **«Да»**: исходная сессия отменена прежним методом, одно ожидающее событие осталось ожидающим, баллы и contributions не изменены.
3. Без своих pending (хотя они есть у других сессий и вне аукциона): сообщение осталось прежним, добавочного предупреждения нет.
4. Ошибка чтения счётчика: выводится ошибка, диалог подтверждения не открывается, остановка не выполняется.

Полная независимая Windows Regression Foundation 1.0.8 обязательна, включая real Qt, Chromium/OBS, Inno Setup и silent installer startup, а также Publication wording gate.

## Ручная проверка Windows

1. Установить только P20-L QA поверх принятой 1.0.8, открыть «Аукцион → Проведение» и проверить знакомое оформление, список, музыку и OBS.
2. При остановке аукциона **без** ожидающих конвертаций увидеть прежний диалог и прежнее поведение «Нет/Да».
3. Если уже имеется настоящее необработанное поступление **этого** аукциона: диалог остановки должен показывать количество и понятное предупреждение. Проверить **«Нет»** — аукцион остаётся запущен/ожидает результата, событие остаётся в «Ожидают применения». **Специально делать донат ради проверки не нужно**: это покрывают изолированные тесты.
4. При сознательном **«Да»** остановка должна работать согласно прежнему контракту: без удаления истории и баллов; ожидающие события остаются в очереди. Проверить, что обычные события **другого** аукциона не вызывают чужое предупреждение.
5. Минимальный/максимальный размер окна, F5, отсутствие побочных изменений таймера, RNG, OBS и музыки.

**Ворота:** exact immutable QA HEAD → native Windows SUCCESS + wording SUCCESS → проверенный ZIP/SHA256/CRC в архиве Google Drive «Обзор_UI_1.0.8» → личная ручная проверка и явное принятие пользователя → отдельное чистое exact-tested-blob promotion с повторным CI и проверкой после объединения. Исходный QA PR не объединять; официального релиза нет.
